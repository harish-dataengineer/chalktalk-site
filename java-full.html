Unit 2 — Classes, Objects & Strings

Classes, Constructors & Overloading

Think of a class as a cookie cutter, and each object as an actual cookie made from it — same shape, different toppings (data). A constructor is what runs automatically the moment a cookie is made, setting its initial toppings.

Overloading just means having several cookie cutters with the same name but different sizes — Java picks the right one based on what ingredients (parameters) you hand it.

Now in exam language:
public class Student { String name; int marks; // Constructor Student(String n, int m) { name = n; marks = m; } // Overloaded constructor Student(String n) { name = n; marks = 0; } }

Two constructors with the same name but different parameter lists — Java chooses which one to run based on what you pass when creating the object (new Student("Ravi", 87) vs new Student("Ravi")).

String, StringBuffer & StringBuilder

High — "difference between" question asked often
Now in exam language:

String is immutable — every modification creates a brand new String object in memory. StringBuffer and StringBuilder are mutable — they modify the same object in place, which is far more efficient inside loops. StringBuffer is thread-safe (synchronized); StringBuilder is faster but not thread-safe.

Differentiate between String, StringBuffer, and StringBuilder with examples.10 marks

Tip: mention immutability first — that's the root reason for every other difference in performance and thread-safety.

Unit 3 — Inheritance & Interfaces

Inheritance — reusing a parent's blueprint

Imagine a general "Vehicle" blueprint with wheels and an engine. A "Car" blueprint can reuse everything from Vehicle and just add its own extra features (like a trunk) — instead of redrawing the whole blueprint from scratch.

Now in exam language:
class Vehicle { void start() { System.out.println("Vehicle starting"); } } class Car extends Vehicle { void honk() { System.out.println("Beep beep!"); } }

Car automatically has access to start() without rewriting it — this is inheritance using the extends keyword.

Method Overriding & Interfaces

Very high — overloading vs overriding is a guaranteed question
Now in exam language:

Overloading is same method name, different parameters, within the same class (decided at compile time). Overriding is a subclass providing its own version of a parent's method with the exact same signature (decided at runtime — this is what makes polymorphism work). An interface is a fully abstract contract — a class that implements it must provide real code for every method the interface declares, which is how Java achieves multiple inheritance of behavior.

Differentiate between method overloading and method overriding with examples.10 marks

Tip: give one short code example for each — examiners want to see the concept demonstrated, not just defined.

Unit 4 — Packages & Collection Framework

Collection Framework — ready-made containers

Very high — ArrayList vs LinkedList, HashMap questions guaranteed

Instead of building your own storage box every time, Java's Collection Framework gives you pre-built containers for different needs: some good for fast lookups, some good for maintaining insertion order, some for storing unique-only items.

Now in exam language — the common ones:
  • ArrayList: resizable array, fast random access, slower inserts in the middle.
  • LinkedList: fast inserts/deletes anywhere, slower random access.
  • HashMap: key-value pairs, no guaranteed order, very fast lookups.
  • TreeMap: key-value pairs, kept in sorted order by key.
  • HashSet: stores only unique elements, no order guaranteed.
ArrayList<String> names = new ArrayList<>(); names.add("Ravi"); names.add("Priya"); HashMap<String, Integer> marks = new HashMap<>(); marks.put("Ravi", 87); marks.put("Priya", 92);
Differentiate between ArrayList and LinkedList with suitable examples.5 marks

Tip: tie the difference back to how each is stored in memory (contiguous array vs. linked nodes) — that's the root cause of every performance difference.

Unit 5 — Exception Handling, Multithreading & JDBC

Exception Handling — planning for things going wrong

Imagine cooking with a backup plan: "try to fry the egg; if the pan catches fire, don't panic — grab the extinguisher (catch it); either way, turn off the stove when done (finally)." That's exactly what try-catch-finally does for risky code.

Now in exam language:
try { int result = 10 / 0; } catch (ArithmeticException e) { System.out.println("Cannot divide by zero"); } finally { System.out.println("This always runs"); }

Checked exceptions (like IOException) must be handled or declared at compile time. Unchecked exceptions (like ArithmeticException) happen at runtime and aren't forced by the compiler.

Multithreading — doing more than one thing at once

Now in exam language:

A thread is a separate path of execution within a program. Java threads move through states: New → Runnable → Running → Blocked/Waiting → Terminated. Synchronization prevents two threads from corrupting shared data by accessing it at the same time.

JDBC — connecting Java to a database

High — JDBC steps asked as a direct question
Now in exam language — the JDBC steps:
  • Load and register the JDBC driver
  • Establish a connection using DriverManager.getConnection()
  • Create a Statement or PreparedStatement
  • Execute the query (CRUD operation)
  • Process the results, then close the connection
Explain the steps involved in connecting a Java application to a MySQL database using JDBC.10 marks

Tip: list the 5 steps in order first, then briefly expand each — structured answers like this score higher than one long paragraph.
