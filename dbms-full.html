Unit 2 — Relational Model & Basic SQL

Primary Key vs Foreign Key vs Candidate Key

Every student in your college has a unique roll number — that's a bit like a Primary Key. No two students share one, and it's how the office identifies you.

Now imagine the library keeps a record of "which roll number borrowed which book." That roll number sitting inside the library's table, pointing back to the student table, is a Foreign Key — it links one table to another.

A Candidate Key is any column that could have been chosen as the primary key.

Now in exam language:

Primary Key: a column (or set of columns) that uniquely identifies each row in a table, and cannot be NULL.
Candidate Key: any minimal set of columns that could uniquely identify a row.
Foreign Key: a column in one table that refers to the primary key of another table.

GROUP BY and HAVING

Imagine sorting your class into groups by branch — that's GROUP BY. If you only want groups with more than 40 students, that filter-after-grouping is HAVING.

Now in exam language:

GROUP BY groups rows sharing a value into summary rows. HAVING filters grouped results.

Write a query to find departments with more than 5 employees, using GROUP BY and HAVING. 5 marks

Tip: write the SELECT ... FROM ... GROUP BY ... HAVING skeleton first.

Unit 3 — ER Model & Advanced SQL

Specialization & Generalization in ER Diagrams

Think of "Vehicle" as a broad category. A Car and a Bike are both vehicles, but each has its own extra details. Splitting Vehicle into more specific types is called specialization.

Generalization is the reverse — pulling common features into one general entity.

Now in exam language:

Specialization: top-down process of defining subclasses. Generalization: bottom-up process of combining common attributes into a superclass.

Joins — the visual way to remember them

An INNER JOIN keeps matching rows. A LEFT JOIN keeps all rows from the left table. A RIGHT JOIN keeps all rows from the right table. A FULL OUTER JOIN keeps rows from both tables.

Now in exam language:

Joins combine rows from two or more tables based on a related column.

Explain the difference between INNER JOIN and LEFT JOIN with an example. 10 marks

Tip: draw small sample tables and show the output.

Unit 4 — Normalization & Transactions

Normalization — the numerical everyone loses marks on

Normalization is the process of splitting a messy large table into smaller, cleaner tables so information is stored properly and repeated updates are avoided.

Worked example — from unnormalized to 3NF

Step 0 — Unnormalized Table (UNF):

101 Ravi DBMS, DSA
Step 1 — Convert to 1NF: remove repeating groups, one course per row.
StudentID StudentName Course
101 Ravi DBMS
101 Ravi DSA
Step 2 — Convert to 2NF: remove partial dependency.
StudentID StudentName
101 Ravi
StudentID Course
101 DBMS
101 DSA
Step 3 — Convert to 3NF: remove transitive dependency.

ACID Properties of a Transaction

Imagine transferring money via UPI. Either the full transfer happens, or none of it does. ACID properties help guarantee reliable database transactions.

Now in exam language:
  • Atomicity: all-or-nothing.
  • Consistency: maintains database rules.
  • Isolation: concurrent transactions do not interfere.
  • Durability: committed changes survive crashes.

Unit 5 — Indexing & Database Tuning

Why indexes exist (and B+ Trees)

A database index works like the index at the back of a textbook — it helps find data faster without scanning everything.

A B+ Tree organizes the index efficiently so searching remains fast even with huge amounts of data.

Now in exam language:

A B+ Tree is a balanced tree data structure used for indexing. It keeps search, insert, and delete operations efficient at O(log n).

Primary vs Secondary Indexing

A primary index is based on the physical ordering of data. A secondary index is an additional index that provides another way to locate data.

Differentiate between primary and secondary indexing with examples. 5 marks

Tip: mention that data can only be physically sorted one way but can have multiple secondary indexes.
