Unit 2 — AVL Trees, B-Trees & Priority Queues

AVL Trees — trees that keep themselves balanced

Imagine a family tree that keeps growing only on one side — eventually it becomes a long, lopsided line instead of a nice branching tree, and finding anyone in it means walking down that entire line one by one.

An AVL Tree is a binary search tree with a built-in rule: after every insertion or deletion, it checks if one side got too much taller than the other, and if so, it automatically "rotates" itself back into balance — like gently rearranging branches so no side gets too heavy.

Now in exam language:

An AVL Tree is a self-balancing binary search tree where the difference in height between left and right subtrees (the balance factor) is always -1, 0, or +1 for every node. Rotations (LL, RR, LR, RL) restore balance after insertions/deletions, keeping search, insert, and delete operations at O(log n).

B-Trees — built for huge, disk-based data

Imagine a library so massive it spans multiple buildings. Instead of one bookshelf per book, each shelf holds several books AND signposts pointing to other shelves. You check fewer signposts overall because each one holds more information at once.

Now in exam language:

A B-Tree is a self-balancing search tree where each node can hold multiple keys and multiple children (not just two, like a binary tree). This makes B-Trees ideal for databases and file systems, where minimizing disk reads matters more than minimizing comparisons.

Priority Queues & Heaps

High — heap operations asked frequently

Imagine a hospital emergency room. Patients aren't treated in the order they arrived — the most critical case always goes first, regardless of queue position. That's exactly what a priority queue does with data: the highest (or lowest) priority item always comes out first.

A Heap is simply the data structure used to implement this efficiently — a special tree shape where the top element is always the most urgent one.

Now in exam language:

A Binary Heap is a complete binary tree satisfying the heap property: in a Max Heap, every parent is greater than or equal to its children; in a Min Heap, every parent is smaller. Insertion and deletion of the top element both run in O(log n).

Explain the insertion operation in a Max Heap with an example.10 marks

Tip: draw the tree at each step as you insert — examiners want to see the "bubble up" process, not just the final tree.

Unit 3 — Divide & Conquer, Greedy Method

Divide and Conquer — break it, solve it, combine it

Imagine sorting a massive pile of exam papers by roll number. Instead of comparing every paper to every other paper, you split the pile in half, ask a friend to sort one half while you sort the other, then merge both sorted piles back together. Each half is easier to handle alone.

Now in exam language:

Divide and Conquer breaks a problem into smaller subproblems of the same type, solves each recursively, then combines their results. Merge Sort and Quick Sort are classic examples — both run in O(n log n) on average.

Greedy Method — best choice right now, every time

Very high — Knapsack & job sequencing asked almost every year

Imagine you have a bag with limited space and a pile of items, each with a different value and weight. A greedy approach says: "grab the most valuable item per kilogram first, then the next best, and so on" — making the locally best choice at every step without looking back.

Now in exam language:

The Greedy Method builds a solution step by step, always choosing the option that looks best at that moment, without reconsidering earlier choices. Classic problems: Job Sequencing with Deadlines (maximize profit by ordering jobs before their deadlines), the Knapsack Problem (fractional version), and Minimum Cost Spanning Trees (Prim's/Kruskal's algorithms).

Solve the Job Sequencing with Deadlines problem for a given set of jobs, profits, and deadlines.10 marks

Tip: sort jobs by profit descending first, then place each job in the latest available slot before its deadline — show this table step by step for full marks.

Unit 4 — Dynamic Programming

Dynamic Programming — remember what you've already solved

Very high — 0/1 Knapsack is a guaranteed question

Imagine solving the same sub-problem again and again while climbing a staircase of decisions — like recalculating "what's the best way to reach step 5" every single time you need it. Dynamic Programming just says: solve it once, write the answer down, and reuse it instead of recalculating.

Now in exam language:

Dynamic Programming solves a problem by breaking it into overlapping subproblems, solving each subproblem only once, and storing the results (memoization/tabulation) to avoid redundant work. Unlike Divide and Conquer, DP subproblems overlap and reuse previous results.

Bellman-Ford & All-Pairs Shortest Paths

Imagine finding the cheapest route between cities, but some roads have tolls that could even be negative (a rebate!). Bellman-Ford carefully checks and rechecks every road multiple times to make sure it hasn't missed a cheaper path — slower than greedy shortest-path methods, but works even with negative weights.

Now in exam language:

Bellman-Ford computes shortest paths from a single source even with negative edge weights, by relaxing all edges repeatedly (V−1 times). All-Pairs Shortest Path algorithms (like Floyd-Warshall, built via DP) find the shortest distance between every pair of nodes in one pass.

Unit 5 — Backtracking & Branch and Bound

Backtracking — try, fail, undo, try again

Very high — N-Queens is a guaranteed question

Imagine solving a maze by walking forward, and the moment you hit a dead end, you don't give up — you walk back to the last junction and try a different path instead. Backtracking is exactly this: try a choice, and if it leads nowhere, undo it and try the next option.

Now in exam language:

Backtracking builds a solution incrementally, abandoning a path as soon as it's clear it can't lead to a valid solution ("pruning"), then trying the next option. Classic problems: N-Queens (place N queens so none attack each other), Sum of Subsets, Graph Coloring, and Hamiltonian Cycles.

Solve the 4-Queens problem using backtracking, showing all steps.10 marks

Tip: draw the 4×4 board and show each placement attempt, including the ones that fail and get backtracked — examiners want to see the pruning, not just the final solution.

Branch and Bound — backtracking's smarter cousin

Backtracking abandons a path only when it's definitely wrong. Branch and Bound is more strategic — it estimates the *best possible outcome* down a path, and abandons it early if that best-case estimate still isn't good enough compared to a solution already found.

Now in exam language:

Branch and Bound explores solution paths like backtracking, but uses a bounding function to estimate the best possible result from a given point — pruning branches whose upper bound can't beat the current best solution. Commonly applied to 0/1 Knapsack and the Travelling Salesperson Problem for more efficient exploration than plain backtracking.
